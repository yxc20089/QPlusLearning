The teacher can look ahead, but we still need to see whether it finishes a real game. That is what this slide measures. Before using the teacher to create training labels, we fix a set of starting games and the rules for passing them.

Look at the grid on the left. Each circle is one complete native game. The four rows are levels one, two, three and five. Each row uses the same five held-out seeds, so there are twenty games altogether. These seeds stay out of training. We also keep a separate set of seeds for the student benchmark. This way, the games we use to qualify the teacher do not become practice examples for Kev.

For each game, we let the teacher play through the actual arcade engine. All four ghosts follow their native behavior, and the engine keeps its movement, power clocks and collisions. A game continues until Pac-Man clears the level or runs out of lives. Losing one life does not end the evaluation. If a watchdog stops a stalled run, that run remains incomplete. We never count it as a win.

Now read the equation below the grid. C with the subscript ell is the clear rate at level ell. Ell simply identifies the level. The letter w with the same subscript is the number of wins, meaning complete level clears. The letter n counts how many games we ran at that level. Here n is five at every level. We observed five clears out of five for each row, so each clear rate is one. All twenty games ate every pellet and completed the level.

That result still has to pass the table on the right. The middle column shows what happened. The last column shows the limits we fixed beforehand. The suite allows up to four life losses in total. The teacher actually lost zero. It also made zero avoidable immediate deaths. Here, avoidable has a precise meaning. From the same native state and random-generator state, another legal direction would have survived the next tile transition, while the chosen direction lost a life before reaching that tile. This is a local safety check. It does not predict whether the alternative survives the rest of the game.

The next two rows check progress. A dry cycle repeats a position sequence without eating a pellet. We reject a streak longer than seven consecutive cycle-closing decisions. The observed longest streak was zero. We separately reject any game with more than 128 consecutive decisions without a pellet. The longest observed dry spell was 67. That allows a useful detour through empty corridors while still rejecting a sustained stall. A brief repeat can remain visible and pass the gate. We chose that rule before qualification.

The last row checks the action contract. A nonterminal direction must enter exactly one adjacent tile. A stationary transition or a jump across several tiles would violate that contract. Both counts were zero.

Finally, follow the boxes along the bottom. We run the complete games, then replay their stored decisions through the same native engine. The verifier checks every recorded state hash, the source hashes and the recomputed metrics. All twenty cold replays passed again when we prepared this slide. This verifies the evidence behind the report. Changing a report's approved flag cannot bypass those checks.

The teacher now qualifies for this declared suite. During dataset generation, each proposed correction still needs its own verified follow-through. A positive training continuation must clear the level with zero life loss and satisfy the loop and stall gates under native replay. That is stricter than the four-loss allowance for the qualification suite. And after training, Kev must play its own held-out complete games. Passing these twenty games gives us empirical evidence for using the teacher. It does not prove that the teacher always survives or finds a globally optimal route.
